# MC. MCP INTEGRATION CONTRACT
외부 앱·계정·서비스를 MCP로 연동할 때의 승인, 설치·설정, 제약 대응을 정의한다. Owner는 `controlplane/shared`이고 직접 Consumer는 `controlplane/AGENTS.MD`다.

## MC.1 AUTHORIZATION BOUNDARY

- PC 파일·명령 전체 접근이 허용되어도 외부 앱, 계정, 서비스의 연결·설치·설정 권한까지 자동으로 포함하지 않는다.
- 기본 기능이나 이미 연결된 MCP로 요청을 충족할 수 있는지 먼저 확인한다.
- 새 MCP 연동이 필요하면 설치·설정 전에 사용자의 명시적 승인을 요청한다.

## MC.2 APPROVAL AND AUTOMATION

승인 요청에는 다음을 포함한다.

- 연동할 앱·서비스와 MCP
- 연동이 필요한 이유와 완료할 작업
- 필요한 권한·의존성·외부 변경
- 사용자가 직접 완료해야 할 로그인·인증·동의가 있는지

사용자가 승인하면 허용된 범위에서 다음을 자동으로 수행한다.

1. 필요한 앱·플러그인·MCP Server와 의존성을 설치한다.
2. 최소 권한으로 연결 정보와 실행 설정을 구성한다.
3. 사용자 로그인·인증·동의가 필요한 지점에서만 사용자 작업을 요청한다.
4. 연결 상태, 권한, 의존성, 최소 호출을 검증한다.
5. 검증되지 않은 설치·연결을 완료로 보고하지 않는다.

## MC.3 CONSTRAINT GUIDE

인증 UI, 관리자 승인, 라이선스, 네트워크·보안 정책, OS 제약, 설치 도구 부재, 사용자 자격 증명 필요 등으로 자동 설치·설정을 완료할 수 없으면 반복 시도나 우회를 중단하고 가이드 문서를 제공한다.

- Task Owner는 `{TA-ID}/output/MCP-SETUP-GUIDE.MD`에 작성한다.
- 다른 Owner는 해당 영역의 기존 Output 경로에 `MCP-SETUP-GUIDE.MD`를 작성한다.
- Output 경로가 정의되지 않았으면 동일한 구조의 Markdown 가이드를 사용자에게 직접 제공한다.

가이드에는 목적, 대상 앱·MCP, 현재 상태, 제약 원인, 사전 조건, 필요 권한, 사용자 수동 절차, 검증 명령·기준, 롤백 방법, 남은 자동화 단계를 포함한다. Password, Token, Cookie, 인증 코드 값은 기록하지 않는다.

## MC.4 COMPLETION

설치 여부, 연결 상태, 적용된 권한, 검증 결과, 사용자가 완료할 작업, 가이드 경로를 구분해 보고한다. 승인받은 MCP 설치·설정 밖의 외부 상태는 변경하지 않는다.
